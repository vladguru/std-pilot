# Сводка

Короткий отчёт о ходе работы (п. 4.2, 5 спеки). Утреннюю сводку ночной смены формирует не этот скилл, а скрипт `scripts/std/morning-summary.mjs` (рабочий процесс `std-morning.yml` публикует её комментарием от `github-actions[bot]` в issue сводок); скилл готовит сводку по запросу владельца и ведёт блок расхода. Читает владелец — деловой язык, без жаргона, не больше экрана текста. Профессиональные слова поясняй в скобках при первом упоминании: «лёгкие модели (быстрые и недорогие, делают основной объём)», «эскалация (передача сложного задания более сильной модели)». Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

По запросу владельца; перед контрольной точкой; по предупреждению `std-run` о расходе; для расчёта остатка ночного бюджета в ночной смене (`std-night`). Утреннюю сводку агент не публикует: это делает скрипт.

## Шаги

1. **Собери состояние из GitHub:** задания поставки по колонкам «Очередь», «В работе», «На ревью», «Ожидает владельца», «Готово» (или по меткам статуса); открытые вопросы `нужен-ответ`; PR с меткой `на-согласовании`; остановленные задания (`стоп`) и причины.
2. **Расход.** Расход токенов по моделям за текущий месяц — `ccusage` по журналам сессий (ночной расход входит в общий и показывается отдельной строкой). Ночной расход берётся из последнего комментария `<!-- night-usage -->` в issue сводок (формат — `.agents/night-shift.md`); комментарий старше 12 часов не используй. Данных нет — напиши «нет данных», оценок не придумывай. Сравни с бюджетом из профиля («Бюджет токенов в месяц», «Ночной бюджет»); исчерпанный ночной бюджет отметь первым пунктом.
3. **Доля лёгких моделей.** Посчитай долю токенов лёгких моделей (Sonnet 5.5, Haiku 5.5, GPT-6.1 Sol) от общего. Цель — не менее 80%. Ниже 80% — признак недостаточной декомпозиции: только отметь это в сводке и предложи `std-plan` уточнить карточки: решение о паузе и пересмотре принимает `std-run`.
4. **Эскалации.** Число эскалаций по модулям за поставку (комментарии «Эскалация:» в заданиях поставки; считай записи); три и более в одном модуле — выдели.
5. **Напиши сводку** в порядке: 1) что ожидает владельца (вопросы и согласования, ссылки); 2) готово; 3) в работе; 4) остановлено и почему; 5) расход и доля лёгких моделей; 6) эскалации. Всё, что требует ответа, — в начале.
6. **Выдай сводку** по запросу владельца ответом в чате. В issue сводок (открытый issue с меткой `сводки`) комментарием публикуй, только если владелец просит оставить сводку в GitHub; утреннюю сводку в назначенное время не публикуй — она формируется скриптом, дубль не нужен.

## Результат

Сводка из шести разделов в чате; блок расхода для ночной смены и комментарий `night-usage` описаны в `.agents/night-shift.md`.

## Стоп-условия и эскалация

- Расход достиг 80% месячного бюджета — вынеси предупреждение первым пунктом и вопрос владельцу (`std-ask`).
- Не меняй задания, метки и PR: скилл только читает и сообщает.
- Не включай в сводку значения секретов и персональные данные.

## Модель и уровень

Работу выполняет субагент Claude `std-progress` (Haiku 5.5, low). Если ты — субагент `std-progress`, выполняй сам. Параметры вызова Codex — `.agents/codex-runs.json`, запись `std-progress` (GPT-6.1 Sol, low).
