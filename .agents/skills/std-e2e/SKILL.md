# Сквозные тесты и исследование интерфейса

Слои e2e, визуальных проверок, доступности и производительности интерфейса (п. 7, 9 спеки). Применяется при параметре профиля «Интерфейс = да». Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

Согласованы AC с пользовательским поведением; изменён интерфейс; нужно воспроизвести ошибку на превью или проверить вид экрана.

## Шаги

1. **Тест по AC.** Для каждого согласованного AC с пользовательским поведением напиши тест Playwright в `tests/e2e/`; идентификатор `AC-NN` — в имени теста или комментарии (по нему CI строит трассировку и протокол приёмки). Тест идёт по поведению пользователя: роли, видимые тексты, а не внутренняя разметка; стабильные селекторы по роли и названию.
2. **Состояния экрана.** Проверь загрузку, пустое состояние, ошибку, отсутствие прав, длинные тексты — они обязательны для каждого экрана.
3. **Доступность.** axe-core в тестах Playwright; управление с клавиатуры, видимый фокус; контраст пар цветов в токенах проверяется автоматически (WCAG 2.2 AA).
4. **Вид экранов.** Снимки Playwright и Storybook против эталона; к PR с интерфейсом прикладываются скриншоты на трёх размерах экрана (телефон, планшет, компьютер) в светлой и тёмной темах. Эталон обновляй только осознанно и пиши, почему.
5. **Производительность.** Lighthouse CI с порогами из `ARCHITECTURE.md`; превышение — замечание, а не повод поднять порог.
6. **Исследование.** Чтобы увидеть реальное поведение на превью, используй agent-browser; консоль, сеть и производительность — Chrome DevTools MCP. Секреты, токены и персональные данные в отчёты не копируй.
7. **Скриншоты для документов** формируются теми же тестами при каждом выпуске (`std-docs`).
8. **Нестабильные тесты.** Автоматический повтор, учёт и карантин с issue на исправление; пропуск без учёта запрещён. Тесты не удаляй и не ослабляй, чтобы CI позеленел.

## Результат

Тесты в `tests/e2e/` с идентификаторами AC, скриншоты в PR, отчёт об исследовании (если запрашивалось).

## Стоп-условия и эскалация

- AC нельзя проверить автоматически — замечание к `SPEC.md`: PR на согласование (`std-spec`), а не отказ от теста.
- Превью недоступно после одной повторной попытки — стоп-условие `std-run` (окружение).
- Ошибка поведения, причина которой неясна, — `std-debug`.

## Модель и уровень

Работу выполняет субагент Claude `std-e2e` (Sonnet 5.5, medium). Если ты — субагент `std-e2e`, выполняй сам. Параметры вызова Codex — `.agents/codex-runs.json`, запись `std-e2e`.
