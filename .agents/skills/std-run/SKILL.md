# Ведение поставки

Дирижёр поставки (п. 4.2 и 5 спеки). Сессия `std-run` расходует токены непрерывно, поэтому работает на лёгкой модели; тяжёлые модели вызываются как субагенты только в перечисленных ниже точках. Команды GitHub — в `.agents/skills/std-ask/references/github.md`. Поправки стандарта к сторонним скиллам — в `.agents/skills/std-task/references/superpowers.md`.

## Когда применять

Есть поставка (milestone) с заданиями-карточками. Скилл запускается днём по просьбе владельца или ночью из `std-night`.

## Шаги

1. **Отвеченные вопросы.** Прочитай ответы владельца (`.agents/skills/std-ask/SKILL.md`, «Приём ответа»), запиши Р-NN, закрой вопросы, сними метки `стоп` с затронутых заданий.
2. **Пауза.** Нет ли открытого issue `пауза`. Есть — остановись в ближайшей безопасной точке.
3. **Отбор.** Из milestone выбери задания, у которых согласованы AC, закрыты зависимости и нет исполнителя. Порядок — по зависимостям и поставке; независимые задания можно вести параллельно (`.agents/skills/dispatching-parallel-agents/SKILL.md`).
4. **Раздача.** Каждое задание выполняет `std-task` (`.agents/skills/std-task/SKILL.md`) на лёгкой модели; захват задания выполняет `std-task` (назначение и комментарий «Захвачено:») до начала работы. Ночью передай исполнителю ограничения `std-night` (не сливать `на-согласовании`, не менять ограничители, не подключать сервисы, не запрашивать токены).
5. **Контроль.** Следи за PR заданий: CI, ревью Codex, превью. Если `std-task` вернул управление с комментарием «Нужен: <скилл>» (субагенты не вызывают других субагентов), вызови указанного субагента сам. Эскалации по лестнице п. 4.2 записываются комментарием «Эскалация:» (метка `эскалация` на задании); три и более в одном модуле за поставку — вызови `std-plan` для пересмотра плана модуля.
6. **Тяжёлые модели** вызываются только для: образца первого экземпляра шаблона (`std-plan`), ступеней 3–4 эскалации, `std-arbiter` и контрольной точки (`.agents/skills/std-gate/SKILL.md`). Вызов — субагентом, не сменой модели своей сессии.
7. **Расход.** Раз в поставку и при подозрении на перерасход открой `std-progress`: доля лёгких моделей должна быть не ниже 80% токенов (профиль «Целевая доля лёгких моделей»). Ниже — признак недостаточной декомпозиции: поручи `std-plan` уточнить карточки (работа при этом не останавливается). При 80% месячного бюджета токенов предупреди владельца (`std-ask`).
8. **Завершение.** Когда все задания поставки слиты, предложи контрольную точку (`std-gate`); новые задания в поставку после этого не принимаются.

## Результат

Задания поставки слиты, остановленные — помечены `стоп` с вопросом владельцу; сводка состояния — в `std-progress`.

## Стоп-условия и эскалация

Останавливай задание (метка `стоп`, комментарий с причиной, вопрос по `std-ask`) только в этих случаях:

1. неясность в бизнес-области профиля («Бизнес-области «неясность = стоп»»), ответа на которую нет ни в `SPEC.md`, ни в `docs/decisions.md`;
2. задание не выполнено на ступени 4 лестницы эскалации;
3. нужно выйти за жёсткие границы `AGENTS.md` или изменить ограничитель;
4. нужен новый внешний сервис, подписка или токен;
5. задание нельзя разбить на части в пределах лимита («Лимит задания»);
6. конфликт слияния или отказ `git push`;
7. обнаружен секрет или уязвимость, которую нельзя устранить в пределах задания;
8. окружение не работает после одной повторной попытки;
9. спор с ревьюером не разрешён третьим мнением (`std-arbiter`) и затрагивает бизнес или безопасность;
10. израсходован месячный бюджет токенов.

Других оснований для остановки нет: технические вопросы решай сам с записью Р-NN. После остановки поставка продолжается заданиями, которые от остановленного не зависят. Обо всех остановках сообщи владельцу одним списком вопросов, а не по одному.

## Модель и уровень

Сессия ведётся в основной сессии на лёгкой модели (Sonnet 5.5, medium; Codex — GPT-6.1 Sol, medium). Субагент `std-run` задан для единообразия, но вложенные вызовы субагентов недоступны, поэтому дирижёр запускается в основной сессии: если эта инструкция передана тебе субагентом `std-run`, выполняй сам только шаги без вызова субагентов и сообщи, что раздачу заданий нужно вести из основной сессии. Параметры вызова Codex — `.agents/codex-runs.json`, запись `std-run`. Краткий стиль `caveman` допустим во внутренней работе.
