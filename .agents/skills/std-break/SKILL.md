# Состязательные тесты

Уровень 10 п. 6.3 спеки: контрольные точки 3–4, для проектов, где в профиле заданы «Критичные функции». Тесты пишет Codex (автор кода — Claude), выполняет CI. Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

По вызову `std-gate` после того, как тяжёлая модель составила перечень атак для критичных функций профиля. Без перечня и без критичных функций скилл не применяется.

## Шаги

1. **Перечень атак.** Возьми его из отчёта контрольной точки: на каждую критичную функцию (идентификаторы `ТР-NN` из профиля) — список атак с ожидаемым поведением. Нет перечня — запроси его у `std-gate`, свои атаки не придумывай вместо тяжёлой модели.
2. **Классы атак:** граничные и недопустимые значения; пустой, огромный и повторяющийся ввод; обход прав и подмена идентификатора другого пользователя; нарушение порядка шагов; повтор запроса и гонки (одновременные запросы); отказ и медленный ответ внешней системы; нарушение инвариантов из `ARCHITECTURE.md`.
3. **Тесты.** Для каждой атаки — автоматический тест в стеке проекта с идентификатором требования и атаки в имени. Тест фиксирует ожидаемое безопасное поведение; тест, который падает на текущем коде, фиксирует найденную ошибку: он оформляется замечанием и сливается вместе с исправлением в задании milestone «Исправления поставки N».
4. **Запуск.** Тесты выполняет CI (Р-44); результат приложи к PR. В `main` отдельным PR попадают только тесты, которые проходят.
5. **Замечания.** Каждая найденная ошибка — issue в milestone «Исправления поставки N» с уровнем по п. 6.5 и шагами воспроизведения.

## Результат

PR с состязательными тестами, перечень атак со статусом «тест написан / найдена ошибка / безопасно», замечания.

## Стоп-условия и эскалация

- Не меняй код проекта, чтобы тест прошёл: тесты проверяют, а не подгоняются.
- Не удаляй и не пропускай существующие тесты.
- Атака, требующая настоящих данных или внешних систем, — выполни на фиктивных данных; иначе вопрос владельцу (`std-ask`).
