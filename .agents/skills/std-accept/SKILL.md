# Приёмка поставки

Стадия 5 (п. 6.4, 7, 10 спеки). Текст для владельца — деловой, без жаргона, понятен с телефона. Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

Все задания поставки слиты и проверены (`std-gate`), превью работает (`std-deploy`).

## Шаги

1. **Проверь готовность.** Критичных замечаний контрольной точки нет, дымовой тест пройден, превью открывается.
2. **Демонстрация.** Подготовь сообщение владельцу: что получилось в терминах бизнеса (3–7 строк); ссылка на превью; скриншоты основных экранов (или видео ключевых сценариев из Playwright); данные для входа в демо — фиктивные, на превью; чего пока нет и что не входит в объём.
3. **«Что проверить вручную за 5 минут».** Короткий перечень из 3–7 действий в обычном браузере: что открыть, что нажать, что должно получиться. Только действия пользователя, без команд и настроек.
4. **Протокол приёмки.** Сформируй из трассировки: требование → AC → тест → результат → дата. Файл формируется автоматически (первая строка «Файл формируется автоматически, не редактировать») и сохраняется в `docs/reports/`. Критерии без теста или с красным тестом выведи отдельным списком.
5. **Вопрос о приёмке.** Оформи по `.agents/skills/std-ask/SKILL.md` один вопрос: А. Принять поставку (рекомендую) — последствие: поставка получает номер версии `vN` и считается принятой; Б. Принять с замечаниями — последствие: замечания станут заданиями следующей поставки; В. Не принимать — последствие: поставка возвращается в работу. Умолчания нет: приёмка — решение владельца.
6. **После ответа.** «Принять» — отметь поставку принятой, `std-gate` ставит тег `vN`; замечания — задания; запись Р-NN «ответ владельца на В-NN».

## Результат

Сообщение с демонстрацией, протокол приёмки в `docs/reports/`, вопрос о приёмке; после ответа — тег `vN` или задания на доработку.

## Стоп-условия и эскалация

- Нет работающего превью или дымовой тест не пройден — приёмку не запрашивай, верни поставку в работу.
- Не принимай поставку за владельца и не ставь тег `vN` без его решения.
- Владельцу не поручай технических действий: проверка идёт по ссылке в браузере.

## Модель и уровень

Работу выполняет субагент Claude `std-accept` (Sonnet 5.5, medium). Если ты — субагент `std-accept`, выполняй сам. Параметры вызова Codex — `.agents/codex-runs.json`, запись `std-accept`.
