# Ночная смена

Работа агентов в отсутствие владельца (п. 5 спеки). Расписание, ночной бюджет и время сводки берутся из профиля `AGENTS.md` («Ночная смена», «Ночной бюджет»). Устройство смены, ночные ограничения, формат расхода и порядок включения — в `.agents/night-shift.md`. Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

Сессию запускает расписание: облачная routine Claude Code (две сессии: 22:00 и 03:00 местного времени, модель Sonnet 5.5). Codex в ночной смене не участвует. Утренняя сводка не входит в сессию: её публикует рабочий процесс `std-morning.yml` (скрипт `scripts/std/morning-summary.mjs`, 07:30 по поясу профиля) комментарием от `github-actions[bot]` в issue сводок, поэтому владелец получает уведомление GitHub даже при общей учётной записи с агентом.

## Шаги

1. **Проверки.** Прочитай `.agents/night-shift.md`. Нет открытого issue `пауза` (иначе смена не начинается). Ночной бюджет профиля не исчерпан: остаток отслеживай по `std-progress` (`.agents/skills/std-progress/SKILL.md`) и по последнему комментарию `<!-- night-usage -->` в issue сводок (бюджет общий для двух сессий). Если данных о расходе нет (в новой облачной среде их часто нет), бери не более трёх заданий за ночную сессию (Р-54).
2. **Отбор.** Бери только задания с согласованными AC, закрытыми зависимостями и без открытых вопросов. Задания в бизнес-областях профиля («Бизнес-области «неясность = стоп»») оставляй на дневное время.
3. **Захват.** Исполнитель (`std-task`) захватывает задание до начала работы — назначением и комментарием «Захвачено:»: так дневная и ночная сессии не берут одно задание.
4. **Работа.** Запусти `std-run` (`.agents/skills/std-run/SKILL.md`) по отобранным заданиям. Перед каждым заданием снова проверяй `пауза`. Вопрос без умолчания, возникший ночью, останавливает только своё задание (метка `стоп`, вопрос по `std-ask`); смена переходит к следующему независимому заданию.
5. **Завершение.** Смена завершается, когда исчерпан ночной бюджет, нет подходящих заданий или поставлена `пауза`. Новые задания после этого не начинаются.
6. **Расход.** В конце каждой сессии оставь в issue сводок комментарий `<!-- night-usage -->` по формату из `.agents/night-shift.md`: строки «Токены за ночь», «Ночной бюджет израсходован», «Доля лёгких моделей», «Заданий выполнено» — нарастающим итогом за ночь. Строку без данных не пиши, оценок не придумывай. Утреннюю сводку не публикуй: её составляет скрипт по этому комментарию (не старше 12 часов) и данным GitHub.

## Результат

Выполненные задания, остановленные задания с вопросами, комментарий `night-usage` в issue сводок. Утреннюю сводку формирует рабочий процесс; сводку по запросу владельца готовит `std-progress`.

## Стоп-условия и эскалация

Ночью запрещено:

- сливать PR с меткой `на-согласовании`;
- изменять ограничители (CI, пороги, правила линтера, защиту веток, `AGENTS.md`);
- подключать внешние сервисы и запрашивать токены;
- превышать ночной бюджет;
- создавать, изменять и удалять расписания: расписания не редактирует ни одна ночная сессия — это делает дневная сессия по ответу владельца (`.agents/night-shift.md`).

Увидев открытый issue `пауза`, остановись в ближайшей безопасной точке: доведи текущее задание до собираемого состояния, новые не начинай и сообщи об этом одной строкой в комментарии `night-usage`. Остальные стоп-условия — как у `std-run`. Если подходящих заданий нет, не придумывай работу: в комментарии `night-usage` укажи «Заданий выполнено: 0».

Включение смены: по одному разрешению владельца через `RemoteTrigger` или скилл `schedule`, порядок описан в `.agents/night-shift.md`; определения routine печатает `scripts/std/night-schedule.mjs`.

## Модель и уровень

Смена ведётся в основной сессии на лёгкой модели (Sonnet 5.5, medium; routine создаётся с моделью `claude-sonnet-5-5`). Субагент `std-night` задан для единообразия: если эта инструкция передана тебе субагентом `std-night`, выполняй сам шаги без вызова субагентов и сообщи, что запускать смену нужно из основной сессии. Параметры вызова Codex — `.agents/codex-runs.json`, запись `std-night`.
