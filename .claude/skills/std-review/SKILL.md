# Ревью

Перекрёстное ревью (п. 6 спеки): Claude пишет — Codex проверяет. Автоматическое ревью PR на GitHub выполняет Codex сам и следует разделу «Правила ревью для Codex» файла `AGENTS.md` (Р-43); этот скилл описывает ручной и локальный запуск и ревью контрольной точки. Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

- Лёгкое ревью — каждый PR между контрольными точками.
- Ревью контрольной точки (`std-review-gate`) — по вызову `std-gate`, по частям (модулям).
- Быстрая проверка PR, изменяющего `SPEC.md`: противоречия с остальным ТЗ.

## Шаги

1. **Режим.** Лёгкое ревью: модель GPT-6.1 Sol, только замечания «критично» (P0) и «важно» (P1), без обсуждений и повторных кругов; «незначительно» в лёгком режиме не пишется. Контрольная точка: GPT-6 Astra · xhigh, полный набор уровней п. 6.3.
2. **Контекст ревьюера.** Ревьюер получает только `SPEC.md`, AC, `ARCHITECTURE.md`, `docs/glossary.md` и проверяемый объём (диф PR или модуль, а для проверки слоёв и использования — и файлы целиком вокруг изменений), без рассуждений автора и без истории его сессии. Агент-автор сам себя не проверяет.
3. **Что проверять в лёгком режиме:** соответствие AC задания и отсутствие лишнего; ошибки и некорректное поведение; безопасность (права, секреты, персональные данные, внешние вызовы); наличие тестов на изменённое поведение; обновление документов и схем.
4. **Что проверять на контрольной точке:** уровни 1–9 п. 6.3 для её номера — ТЗ, дизайн, архитектура и план, соответствие, качество, тесты, визуальное ревью, документация и схемы, безопасность (`std-security`).
5. **Вызов Codex.** Возьми запись скилла (`std-review` или `std-review-gate`) в `.agents/codex-runs.json` и выполни на собственном исполнителе команду из поля `command` записи, добавив в конце текст задачи: `<command> "<что проверить, номер PR, пути к материалам>"`. Codex читает репозиторий сам; ответ сохрани в файл и опубликуй как комментарий. Если сам вызов завершился ошибкой (не только программы нет), считай Codex недоступным. Облачные задачи Codex не запускай (Р-44).
6. **Если Codex недоступен**, ревью выполняет субагент Claude с чистым контекстом; в PR укажи «ревью не перекрёстное». Отсутствие перекрёстного ревью слияние PR не блокирует (критичные замечания запасного ревью блокируют, как обычно), но на контрольной точке перекрёстное ревью обязательно: если Codex недоступен и там, зафиксируй это в отчёте как риск.
7. **Оформи замечания.** Уровни: **критично** — блокирует слияние или приёмку; **важно** — исправляется в рамках контрольной точки либо записывается в отчёт с обоснованием; **незначительно** — записывается в отчёт. Замечание: уровень, файл и строка, суть, чем грозит; на контрольной точке — ещё и как проверить исправление. В лёгком режиме — один комментарий к PR со списком замечаний, а при отсутствии критичных и важных — фраза «Критичных и важных замечаний нет»; критичное замечание блокирует слияние: опубликуй ревью с событием `REQUEST_CHANGES` (команда в справочнике GitHub). На контрольной точке — issue в milestone «Исправления поставки N».
8. **Споры.** Автор излагает возражение, ревьюер отвечает один раз; при отсутствии согласия решает `std-arbiter` (`.agents/skills/std-arbiter/SKILL.md`).

9. **Особые случаи.** AC задания нет в `SPEC.md` или `SPEC.md` — черновик: замечание «важно» и вопрос владельцу по `std-ask`, а не догадка. Найден секрет в коде или истории — «критично»: секрет считается скомпрометированным, не копируй его значение в комментарий; стоп-условие `std-run` и `std-security`.

## Результат

Список замечаний с уровнями; для PR — комментарий с итогом «критичных нет» или перечнем; для контрольной точки — issue и раздел отчёта.

## Стоп-условия и эскалация

- Слияние блокирует только «критично». Замечание «важно» автор исправляет в заданиях контрольной точки.
- Спор по бизнесу или безопасности не решает арбитр — вопрос владельцу (`std-ask`).
- Ревьюер не правит код автора и не меняет ограничители.

## Модель и уровень

Работу выполняют субагенты Claude `std-review` (Sonnet 5.5, high — для запасного ревью) и `std-review-gate` (Opus 5.5, xhigh — для запасного ревью контрольной точки). Если ты — субагент `std-review` или `std-review-gate`, выполняй сам. Основной ревьюер — Codex; параметры вызова — `.agents/codex-runs.json`, записи `std-review` (GPT-6.1 Sol, high) и `std-review-gate` (GPT-6 Astra, xhigh).
