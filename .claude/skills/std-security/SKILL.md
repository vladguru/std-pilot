# Проверка безопасности

Уровень 9 п. 6.3 спеки: контрольные точки 2–5. Метод — по списку ниже, замечания — по уровням п. 6.5. Команды GitHub — в `.agents/skills/std-ask/references/github.md`.

## Когда применять

По вызову `std-gate` (`.agents/skills/std-gate/SKILL.md`); для PR, который трогает права, данные, секреты или внешние вызовы, — по просьбе `std-review`.

## Шаги

1. **Материалы.** `ARCHITECTURE.md`, модель угроз (`docs/dev/`), перечень персональных данных и сроков хранения, диф с предыдущей принятой версии, `SPEC.md`.
2. **Проверка Claude.** Тяжёлая модель просматривает объём по темам: модель угроз и её соответствие коду; права и проверки доступа на каждом входе; обработка и хранение персональных данных, маскирование в журналах и демо-данных; секреты в коде, истории и конфигурации; внешние вызовы (адреса, разрешения, повторы, доверие к ответам); внедрение инструкций через данные (issue, комментарии, содержимое пользователей); зависимости и образы.
3. **Проверка Codex.** Вызови Codex по записи `std-security` из `.agents/codex-runs.json` на собственном исполнителе; для PR можно запросить комментарий `@codex security review`. Облачные задачи Codex не запускай (Р-44).
4. **Сведение.** Объедини результаты двух проверок, убери дубли, определи уровень каждого замечания: **критично** (блокирует приёмку), **важно**, **незначительно**. Для каждого — файл и строка, угроза, способ проверить исправление.
5. **Оформление.** Каждое замечание — issue в milestone «Исправления поставки N»; описание не содержит значений секретов и настоящих персональных данных.
6. **Владельцу** уходят только решения по составу персональных данных, правам доступа и новым внешним сервисам (`std-ask`); исправление уязвимостей — обычные задания.

## Результат

Единый перечень замечаний по безопасности с уровнями; раздел «Безопасность» отчёта контрольной точки.

## Стоп-условия и эскалация

- Найден действующий секрет — стоп-условие `std-run`: сообщи владельцу, секрет считается скомпрометированным и подлежит замене; не копируй его значение в отчёты.
- Уязвимость, которую нельзя устранить в пределах задания, — метка `стоп`, вопрос владельцу.
- Не ослабляй проверки безопасности ради прохождения CI.

## Модель и уровень

Работу выполняет субагент Claude `std-security` (Opus 5.5, xhigh). Если ты — субагент `std-security`, выполняй сам. Проверка Codex — GPT-6 Astra, xhigh; параметры вызова — `.agents/codex-runs.json`, запись `std-security`.
